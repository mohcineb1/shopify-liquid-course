# Recherche vérifiée — chapitre 24

- Les marchands peuvent générer des theme blocks dans les sections existantes qui acceptent les theme blocks.
- Une section accepte tous les theme blocks en déclarant `@theme` dans l’attribut `blocks` de son schema.
- Les blocs générés ne sont pas des sections. Shopify les enveloppe par défaut dans une section plateforme `_blocks.liquid` lorsqu’un marchand génère un bloc dans une nouvelle section.
- Un thème peut remplacer ce wrapper en ajoutant `sections/_blocks.liquid`.
- `_blocks.liquid` doit déclarer les types `@theme` et `@app`, des presets, `{% content_for 'blocks' %}`, et ne doit pas déclarer l’attribut `templates`, y compris dans `enabled_on`/`disabled_on`; sinon erreur dans l’éditeur et impossibilité pour les marchands d’utiliser la section.
- Le wrapper n’est pas une section standard : pas de rendu manuel via `{% section '_blocks' %}` et elle n’est pas disponible comme section à ajouter dans l’éditeur.
- Les blocs générés restent du code à tester : Shopify indique qu’ils peuvent produire des erreurs, des résultats inattendus, ou ne pas respecter intégralement accessibilité et performance; l’équipe du thème reste responsable de la revue.
- Après conservation, le fichier Liquid du bloc généré est ajouté au dossier `blocks/`.
- Pour les app blocks : sections JSON devraient prendre `@app`; les app blocks statiquement rendus ne sont pas supportés. `@app` ne prend pas `limit`. App blocks et theme blocks de premier niveau peuvent être traités par `_blocks.liquid`.
