# Research notes — ch-70 Commerce Surfaces

Verified 2026-08-15.

- Section Rendering API: request up to five section IDs with `sections` parameter; response is JSON mapping IDs to HTML; a failed section can be `null` even with HTTP 200; section settings cannot be specified in request; the requested page URL supplies Liquid resource context; use locale-aware `window.Shopify.routes.root` or current pathname. For cart changes, Shopify suggests considering bundled section rendering. Source: https://shopify.dev/docs/api/ajax/section-rendering
- Collection template: Liquid `collection` supplies page data; collection filtering uses storefront filtering; sorting uses `sort_by` URL parameter and `collection.sort_options`, `sort_by`, `default_sort_by`; collection products are limited to 50 per page and must paginate. Remote products are automatically surfaced when using Liquid `collection.products`, but are not supported by themes surfacing collection products through APIs. Source: https://shopify.dev/docs/storefronts/themes/architecture/templates/collection
- High-variant product support: `product.variants` returns max 250; audit full-variants and `product | json` patterns. Use `product.options_with_values`, `product_option_value` attributes and option-values parameter/Section Rendering to avoid overfetch. A non-existent option combination may return null selected variants. Exact theme preview/developer-preview behavior remains `[VERIFY]` for capstone.
  Source: https://shopify.dev/docs/storefronts/themes/product-merchandising/variants/support-high-variant-products
- Product recommendations: related products auto-generated; complementary recommendations manually configured; both type/configuration and tracking/app availability must be `[VERIFY]`. Source: https://shopify.dev/docs/storefronts/themes/product-merchandising/recommendations
